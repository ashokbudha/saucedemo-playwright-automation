## 5.1 Test Case Organization

The detailed test cases are organized by test scenario. Each scenario contains test cases that cover the relevant functional and non-functional aspects of the application.

The following structure is used:

| Scenario ID | Scenario                         | Test Case ID Range                |
| ----------- | -------------------------------- | --------------------------------- |
| **TS-001**  | Authentication                   | TC-LOGIN-001 – TC-LOGIN-012       |
| **TS-002**  | Product Catalog                  | TC-PRODUCT-001 – TC-PRODUCT-009   |
| **TS-003**  | Product Sorting                  | TC-SORT-001 – TC-SORT-006         |
| **TS-004**  | Shopping Cart                    | TC-CART-001 – TC-CART-012         |
| **TS-005**  | Checkout                         | TC-CHECKOUT-001 – TC-CHECKOUT-015 |
| **TS-006**  | Order Placement                  | TC-ORDER-001 – TC-ORDER-007       |
| **TS-007**  | Navigation and Application State | TC-NAV-001 – TC-NAV-010           |
| **TS-008**  | Footer Links and Information     | TC-FOOTER-001 onward              |

### Test Case Identification

Each test case has a unique ID based on its functional area. For example:

* `TC-LOGIN-001` — Authentication test case
* `TC-PRODUCT-001` — Product catalog test case
* `TC-SORT-001` — Product sorting test case
* `TC-CART-001` — Shopping cart test case
* `TC-CHECKOUT-001` — Checkout test case
* `TC-ORDER-001` — Order placement test case
* `TC-NAV-001` — Navigation test case
* `TC-FOOTER-001` — Footer test case

This naming convention makes test cases easier to identify, reference, execute, and maintain.
