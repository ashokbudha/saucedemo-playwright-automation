
# SauceDemo Web Application



**Application:** SauceDemo <br>
**Website:** www.saucedemo.com


# 1. System Overview

## 1.1 Introduction

SauceDemo is a web-based demonstration e-commerce application designed to simulate common online shopping activities. The application provides a simplified shopping workflow that allows users to authenticate, browse products, manage a shopping cart, complete checkout information, and place an order.

The application is suitable for practicing software testing and test automation because it provides several common e-commerce workflows and predefined user accounts with different authentication behaviors.

### 1.2 Authentication

SauceDemo provides a predefined authentication system for testing different user behaviors. Users do not create an account through a registration process; instead, the application provides a set of predefined usernames that can be used to access the system.

The application provides the following predefined users:

| Username                  | Purpose / Expected Behavior                                       |
| ------------------------- | ----------------------------------------------------------------- |
| `standard_user`           | Standard user account for normal application workflows            |
| `locked_out_user`         | Account intended to represent a locked-out user                   |
| `problem_user`            | User account that demonstrates known application problems         |
| `performance_glitch_user` | User account intended to demonstrate performance-related behavior |
| `error_user`              | User account intended to demonstrate error-related behavior       |
| `visual_user`             | User account intended to demonstrate visual-related behavior      |

The password provided for all predefined users is:

`secret_sauce`

Authentication is therefore based on predefined test credentials rather than user registration. The different user accounts allow testers to evaluate how the application behaves under normal and predefined abnormal conditions.


## 1.3 Product Catalog

After successful login, users can access the product inventory from the main application page.

Each product contains:

* Product name
* Product description
* Product image
* Product price
* Add-to-cart functionality

Individual product details can also be accessed through the product's dedicated product page.

The product inventory does not provide product categories, keyword search, or filtering functionality. However, users can sort the available products using:

* Name: A to Z
* Name: Z to A
* Price: Low to High
* Price: High to Low

## 1.4 Shopping Cart

Users can add products to a shopping cart from the product inventory. The cart provides access to the products selected by the user and allows products to be removed before checkout.

The cart can be accessed through the shopping cart interface, after which the user can proceed to the checkout process.

## 1.5 Checkout

The application provides a simplified checkout workflow.

During checkout, the user is required to provide basic information, including:

* Name
* Postal/ZIP code

The application does not implement a real payment-processing system. Instead, it simulates the checkout process and displays the order summary, including the calculated total.

After the order is successfully placed, the application displays an order-completion confirmation.

## 1.6 Navigation

The application provides a hamburger menu for navigating between major application functions. The menu includes:

* All Items
* About
* Logout
* Reset App State

The Reset App State option allows the application's current state to be reset.

## 1.7 Footer

The application contains a footer with links to the application's social media profiles, including:

* Twitter
* Facebook
* LinkedIn

The footer also contains copyright information.

## 1.8 Overall User Flow

The primary shopping workflow can be summarized as:

**Login → Browse Products → Select Product → Add to Cart → Review Cart → Checkout → Enter Required Information → Review Order → Place Order → Order Confirmation**

This workflow represents the primary end-to-end user journey that will be considered when developing the test strategy and automation scope.
